## 🧠 Skills_and_Capabilities.md (AI 개발 에이전트 핵심 역량 가이드)## 1. 개요 (Overview)
본 문서는 AI 개발 에이전트가 프로젝트를 구현할 때 반드시 확보하고 적용해야 하는 시니어 아키텍트 수준의 기술적 역량(Skills)과 문제 해결 시나리오를 정의합니다. AI 에이전트는 코드를 생성할 때 아래의 예외 처리, 성능 최적화, 보안 규칙을 무조건 준수해야 합니다.
------------------------------
## 2. 핵심 기술 역량 가이드 (Core Technical Capabilities)## 👥 2.1. 고성능 실시간 미디어 파이프라인 제어 (WebRTC/SFU Skill)

* 메모리 누수 방지: 화상채팅 룸이 종료되거나 유저가 비정상 종료(네트워크 단절 등)될 때, LiveKit SFU 서버와 Node.js 백엔드 간의 오디오 스트림 커넥션 및 미디어 트랙 리스너를 반드시 명시적으로 해제(destroy(), removeAllListeners())해야 합니다.
* 스트림 동기화: 화자 분리(Diarization) 정확도를 높이기 위해, 들어오는 오디오 데이터 파이프라인의 타임스탬프 왜곡을 방지하고 순서(Sequence)를 보장하는 버퍼링 로직을 구현해야 합니다.

## 🧱 2.2. 분산 동시성 제어 및 최적화 (CRDT/WebSocket Skill)

* 디바운스(Debounce) 기반 DB 저장: 수십 명의 유저가 동시에 문서를 타이핑할 때 발생하는 모든 웹소켓 이벤트를 매번 MongoDB에 저장하면 DB가 마비됩니다. 메모리 상에서 Yjs Update를 결합(Merge)한 후, 최종 상태를 3초~5초 간격으로 디바운스하여 MongoDB에 백그라운드로 저장하는 쓰기 지연 최적화 능력을 발휘해야 합니다.
* 소켓 버퍼 오버플로우 방지: 대규모 트래픽 발생 시 웹소켓 백프레셔(Backpressure)를 관리하여, 서버 메모리가 고갈되지 않도록 메시지 큐 시스템을 설계해야 합니다.

## 🎙️ 2.3. AI API 비용 최적화 및 회복 탄력성 (AI Integration Skill)

* 묵음 감지 (VAD - Voice Activity Detection): 화상채팅 중 사용자가 말을 하지 않는 묵음 구간을 백엔드에서 1차적으로 필터링하여, 불필요한 STT(Deepgram/Whisper) API 호출 비용을 최소화(최소 30% 절감 목표)하는 로직을 작성해야 합니다.
* 장애 복구 (Exponential Backoff): AI API(OpenAI, Deepgram 등)가 일시적인 트래픽 과부하로 인해 429(Too Many Requests) 또는 5xx 에러를 반환할 때, 시스템이 즉시 다운되지 않고 지수 백오프(재시도 간격을 점진적으로 늘리는 방식) 알고리즘을 적용해 요청을 안전하게 재시도해야 합니다.

------------------------------
## 3. 보안 및 데이터 무결성 규칙 (Security & Integrity)

* 비정형 데이터 검증 (Sanitization): MongoDB의 특성상 플러그인 모듈이 자유로운 JSON 구조를 저장할 수 있지만, 악성 스크립트 삽입(XSS)이나 인젝션을 방지하기 위해 data: Object 내부 필드를 강하게 필터링하고 검증하는 화이트리스트 기반 유효성 검사 코드를 작성해야 합니다.
* 상태 동기화 복구: 네트워크 단절 후 재연결된 클라이언트가 과거의 잘못된 스냅샷으로 문서를 덮어쓰지 않도록, 서버가 항상 최신 State Vector를 기준으로 클라이언트의 이벤트를 검증하고 동기화를 승인해야 합니다.
